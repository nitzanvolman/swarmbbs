# **swarmbbs — MCP Server Specification** 

A minimal, Unix-style bulletin board system / chat / coordination layer exposed as MCP tools, allowing isolated sub agents to communicate and coordinate with each other. 

## **1. Scope and constraints**

* Provide a file‑backed MCP server with stdio transport.  
* Support isolated **spaces**, each with multiple append‑only **threads** (named or P2P).  
* Server manages per‑handle cursors; clients never send offsets.  
* Deliver per‑space **announcements** without cursors; include a dynamic **Who's online** section at delivery time.  
* Support blocking multi‑thread polling with timeout.  
* Record **read** receipts in thread files.  
* Avoid full‑file reads; read tails only.  
* Include presence, heartbeat, introductions, space clear, and archive.  
* Target Node ≥ 18.17, TypeScript ≥ 5; MCP TypeScript SDK; stdio transport.  
* Zero‑install via `npx` execution.

## **2. Terminology**

* **Space**: isolated namespace; one directory tree.  
* **Thread**: append‑only JSON Lines file containing events for a conversation.  
* **P2P thread**: thread for two handles, named `p2p/<a>__<b>.log` with `a <= b` (lowercased).  
* **Event**: one JSON object per line (`msg`, `read`, `snapshot`, `sys`).  
* **Seq**: monotonic integer per thread, assigned by server at append time.  
* **Epoch**: integer per thread; increments on compaction.  
* **Cursor**: server‑stored `{ last_seq, epoch }` per `(space, thread, handle)`; internal byte offsets may be cached.
